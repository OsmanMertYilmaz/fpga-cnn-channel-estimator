# FPGA-Based CNN Channel Estimator

A small convolutional neural network (CNN) that denoises pilot-based LS channel estimates in a 5G NR–like
OFDM receiver, and the flow that takes it to an FPGA.

Pipeline:

```
NumPy channel simulation ─▶ Keras CNN (FP32) ─▶ QKeras 8-bit QAT ─▶ hls4ml (HLS C++) ─▶ Vitis HLS (synthesis, co-sim)
```

## Results

| Estimator | Parameters | NMSE, 3 km/h, 10 dB | NMSE, 120 km/h, 10 dB | Validation NMSE (mixed 0–30 dB) |
| --- | --- | --- | --- | --- |
| LS + linear interpolation | – | −11.6 dB | −10.5 dB | −10.2 dB |
| CNN `cnn_snr_p72`, FP32 | 4,080 | −16.7 dB | −14.7 dB | −15.6 dB |
| CNN `cnn_snr_p72_wide`, FP32 | 15,064 | −17.2 dB | −15.0 dB | −16.3 dB |
| CNN `cnn_snr_p72`, 8-bit | 4,080 | not yet measured | not yet measured | −15.6 dB |
| CNN `cnn_snr_p72_wide`, 8-bit | 15,064 | not yet measured | not yet measured | −16.2 dB |
| LMMSE (ideal statistics, upper bound) | – | −22.7 dB | −17.9 dB | – |

- 8-bit quantization costs about 0 dB.
- The C++ generated by hls4ml is **bit-exact** with the QKeras model (100% of 1,008,000 output values over
  500 grids).
- Known weakness: at 3 km/h and above 25 dB SNR, the CNN hits an error floor (about −29 dB) and falls behind
  LS (−31.6 dB). A practical fix is to bypass the CNN at high SNR and use the LS output directly.

![CNN vs. classical estimators](results/nmse_compare.png)

Averaged over TDL-A/B/C, 300 ns delay spread. Detailed numbers are in `results/*.csv`.

## System model

| Setting | Value |
| --- | --- |
| Grid | 72 subcarriers (6 RB) × 14 OFDM symbols (1 slot) |
| Subcarrier spacing, carrier frequency | 15 kHz, 3.5 GHz |
| Antennas | 1 × 1 (SISO) |
| Pilots (DMRS) | Symbols 2 and 11, every other subcarrier (comb-2), fixed QPSK |
| Channel | 3GPP TR 38.901 TDL-A/B/C, Jakes Doppler (sum of sinusoids) |
| Training range | Delay spread 50–300 ns, speed 0–120 km/h, SNR 0–30 dB |

**Simplifications:**
- The channel is generated directly in the frequency domain. The CP is assumed longer than the maximum delay,
  and intra-symbol Doppler (ICI) is ignored.
- No CFO or timing errors.
- LMMSE knows the true channel statistics, so it is an upper bound.
- The CNN is given the true SNR; a real receiver would have to estimate it.

**Model:** The LS estimate is first spread over the full grid by linear interpolation. The CNN only removes
the noise from this grid (residual connection: `output = h_LS + correction`). The input has 3 channels: real
part, imaginary part and a constant SNR plane. The network is four 3×3 convolutions (16-16-8-2 or
32-32-16-2 channels).

## Installation

Requires Python 3.11; TensorFlow 2.15 and QKeras 0.9 work together on this version.

```bash
git clone https://github.com/OsmanMertYilmaz/fpga-cnn-channel-estimator.git
cd fpga-cnn-channel-estimator
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

On macOS without Python 3.11: `brew install python@3.11`, then `/opt/homebrew/bin/python3.11 -m venv .venv`.

## Usage

Run the steps in order; each step's output is the next step's input. Trained models are included in the
repository, so steps 3 and 4 can be skipped. The dataset is not included and must be generated with step 2.
Run times are for an Apple M3 (CPU only).

### 1. Classical baselines (~30 s)

```bash
.venv/bin/python run_reference.py
```

Computes NMSE vs. SNR curves for LS + interpolation and LMMSE.
Outputs: `results/nmse_reference.png`, `results/nmse_reference.csv`.

### 2. Dataset (~5 s)

```bash
.venv/bin/python dataset.py
```

Generates 16,000 training and 2,000 validation grids: `data/train.npz`, `data/val.npz` (~277 MB).
Channel type, delay spread, speed and SNR are drawn at random for each grid. Grids are stored as 12×14
patches; the training script regroups them to the requested size.

### 3. FP32 training (6–10 min per model)

```bash
# small model, full grid, SNR input
.venv/bin/python train.py --name cnn_snr_p72 --snr-input --patch 72 --filters 16 16 8

# wide model
.venv/bin/python train.py --name cnn_snr_p72_wide --snr-input --patch 72 --filters 32 32 16
```

| Option | Meaning |
| --- | --- |
| `--name` | Model name → `models/<name>.keras` |
| `--patch` | Subcarriers processed at once: 12, 24, 36 or 72 (full grid) |
| `--filters` | Channel counts of the hidden layers |
| `--snr-input` | Feed the SNR as a third input channel |
| `--no-weight` | Disable the SNR-weighted loss (on by default; makes sure high-SNR samples are learned too) |

### 4. Comparison (~1–2 min)

```bash
.venv/bin/python evaluate.py --models cnn_snr_p72 cnn_snr_p72_wide --out nmse_compare
```

Compares the given models with LS and LMMSE on the same test scenarios (3 and 120 km/h, 0–30 dB).
Outputs: `results/nmse_compare.png`, `results/nmse_compare.csv`. Only reads FP32 `.keras` models.

### 5. 8-bit quantization-aware training (8–12 min per model)

```bash
.venv/bin/python quantize.py --name cnn_snr_p72
.venv/bin/python quantize.py --name cnn_snr_p72_wide
```

Starts from the FP32 weights and fine-tunes the QKeras version of the same architecture.
Output: `models/q_<name>.weights.h5`.

| Quantity | Format | Range, step |
| --- | --- | --- |
| Input (h_LS, SNR plane) | `ap_fixed<12,4>` | ±8, 1/256 |
| Weights, biases | `ap_fixed<8,1>` | ±1, 1/128 |
| Hidden activations | `ap_ufixed<8,2>`, last hidden layer `ap_ufixed<8,3>` | 0–4 / 0–8 |
| Correction output | `ap_fixed<10,3>` | ±4, 1/128 |

### 6. hls4ml conversion and bit-exact check (~1–2 min per model)

```bash
.venv/bin/python hls_convert.py --name cnn_snr_p72
.venv/bin/python hls_convert.py --name cnn_snr_p72_wide
```

- Converts the model into a Vitis HLS project under `hls/<name>/` (`io_stream`, `Strategy=Resource`).
- Compiles the generated C++ with the local compiler and compares it with the QKeras output. Expected output
  (the script prints in Turkish: "output values, bit-exact match, max difference"):

```
cnn_snr_p72: 1008000 çıktı değeri, bit-bit eşleşme %100.000, max fark 0.00e+00
```

- Test vectors for C-sim and co-sim are written to `hls/<name>/tb_data/` (20 grids).
- `--reuse N` sets the ReuseFactor (default 32). It only affects synthesis: a larger value means fewer
  resources but higher latency.

### 7. Synthesis with Vitis HLS

Vitis HLS runs only on Linux or Windows x86_64. On such a machine, after the installation and step 2:

```bash
source /tools/Xilinx/Vitis_HLS/<version>/settings64.sh   # adjust to your install path
.venv/bin/python hls_convert.py --name cnn_snr_p72 --build --reuse 32
.venv/bin/python hls_convert.py --name cnn_snr_p72_wide --build --reuse 32
```

`--build` runs C simulation, synthesis and C/RTL co-simulation in sequence.
Reports are in `hls/<name>/chest_prj/solution1/syn/report/` (resource usage, latency, II).

The target board is the ZCU104 (`xczu7ev-ffvc1156-2-e`) at 200 MHz. For another board, change `PART` and
`CLOCK_NS` in `hls_convert.py`.

## Repository layout

```
├── ofdm_channel.py     OFDM grid, TDL-A/B/C channel, DMRS pattern, received pilots
├── estimators.py       LS + interpolation, 2D LMMSE, NMSE
├── run_reference.py    Step 1: classical baseline curves
├── dataset.py          Step 2: dataset, patch transforms, SNR input plane
├── train.py            Step 3: FP32 CNN architecture and training
├── evaluate.py         Step 4: CNN / LS / LMMSE comparison
├── quantize.py         Step 5: QKeras 8-bit QAT, number formats
├── hls_convert.py      Steps 6–7: hls4ml conversion, bit-exact check, Vitis HLS build
├── models/             Trained FP32 (.keras) and 8-bit (q_*.weights.h5) models
├── hls/                HLS C++ projects generated by hls4ml (firmware/, tb_data/, build_prj.tcl)
└── results/            NMSE plots and CSVs, training histories
```

The older models in `models/` (`cnn_fp32`, `cnn_fp32_mse`, `cnn_snr`, `cnn_snr_wide`) are kept for the
experiment comparison. The hardware candidates are `cnn_snr_p72` and `cnn_snr_p72_wide`.

Code comments, script output and plot labels are in Turkish.

## Known pitfalls

- **QKeras + `load_model` hang:** after QKeras is imported, `tf.keras.models.load_model` (Keras 2.15, `.keras`
  file) loops forever. The scripts load the FP32 model before importing QKeras and hls4ml; keep this order in
  new scripts.
- **TDL table values:** the delays and powers in `ofdm_channel.py` are taken from TR 38.901
  Tables 7.7.2-1/2/3; check them against the standard before relying on them.
- **NumPy version:** TensorFlow 2.15 needs NumPy 1.26; it does not work with NumPy 2.x.
